# 个人网站完整总体方案

> 文档状态：第一版原型已完成，V2 内容发布基础设施已在本地实现
> 版本：v0.1  
> 建立日期：2026-08-13  
> 适用范围：产品、视觉、交互、内容、技术、部署和持续运营  
> 更新原则：重要变更须同时更新本文与对应 ADR

## 1. 项目摘要

本项目建设一个以个人表达、研究工作、文字记录和摄影档案为核心的长期个人网站。网站不是简历模板、社交媒体聚合页或单纯摄影作品集，而是一套可以逐年增长的“个人数字档案馆”。

网站采用“编辑部式个人档案馆 + 沉浸式数字暗房”的双重体验：

- 首页及文字内容使用明亮、安静、接近独立刊物的编辑式设计。
- 首页不展示照片，依靠字体、网格、内容和微交互建立气质。
- 进入影集后切换为更深、更沉浸的观看环境。
- 真实高清照片承担视觉表达，代码负责组织、加载、转场和探索方式。
- 交互体验应丰富，但始终服务于内容理解和观看节奏。

第一版不追求一次性填满所有栏目，而是建立稳定的设计语言、内容模型和运行基础，使网站可以持续更新多年。

## 2. 已确认目标与约束

### 2.1 核心目标

1. 建立具有明确个人气质、不过度模板化的网站。
2. 首页以文字和排版为主，不展示照片。
3. 为照片提供独立、沉浸并支持探索的展示空间。
4. 交互丰富且细腻，桌面、手机、键盘和触屏均可完整使用。
5. 使用真实、高清、许可清晰的素材，不以生成式插画充当内容。
6. 兼顾访问速度、搜索可发现性、无障碍和长期维护成本。
7. 建立可预览、可回滚、可备份、可迁移的部署体系。

### 2.2 非目标

第一版暂不包含：

- 社交网络、关注、点赞或用户评论系统。
- 电商、照片销售或在线付款。
- 复杂会员体系。
- 全站 3D 场景或游戏化导航。
- 为了显得“先进”而添加聊天机器人。
- 自动抓取个人社交平台的所有内容。
- 未经筛选的大规模照片网盘式展示。

### 2.3 不可破坏的产品原则

- 首页无照片是稳定约束；如将来调整，应先新增正式决策记录。
- 影集可以实验，但基本导航必须清楚。
- 所有动画都必须有静态或低动态替代体验。
- 网站内容的正常阅读不能依赖 WebGL、Canvas 或持续动画。
- 不以高 Awwwards 风格为目标牺牲速度和易用性。

## 3. 用户与使用场景

### 3.1 主要访问者

- 想了解本人研究、工作与兴趣的同行或合作伙伴。
- 通过搜索、文章或项目链接进入的专业访客。
- 关注摄影、城市和日常记录的朋友。
- 未来的自己：回看数年积累的作品、文字和阶段状态。

### 3.2 关键场景

1. 访客在 10 秒内知道“我是谁、关注什么、网站能看什么”。
2. 访客不经过首页照片轰炸，也能感受到明确的视觉个性。
3. 访客进入影集后，可以按故事阅读，也可以自由探索。
4. 访客能快速找到研究项目、随笔或联系方式。
5. 本人可以在不重做页面的情况下新增一组影集、一篇随笔或一个项目。
6. 网站迁移到另一家托管商时，内容和素材不会被某个平台锁定。

## 4. 信息架构

### 4.0 当前已实现的 V2 路由

当前代码已经先落地照片内容链路，作为正式项目、随笔页面之前的可运行切片：

```text
/
├── /photos
├── /photos/[album-slug]
├── /photos/[album-slug]/[photo-slug]
├── /studio                 # owner-only 发布工作台
├── /api/photos             # 已发布照片目录
├── /api/albums/[slug]
├── /api/studio/photos      # owner-only 草稿与发布
└── /media/photos/[id]      # 仅提供已发布网页版本
```

`/projects`、`/notes`、`/about` 仍按内容准备情况分阶段拆分；首页现有锚点内容继续保留，避免一次迁移影响已完成的交互。

### 4.1 第一版正式页面

```text
/
├── /projects
│   └── /projects/[slug]
├── /photos
│   ├── /photos/explore
│   └── /photos/[album-slug]
├── /notes
│   └── /notes/[slug]
├── /about
├── /now
└── /404
```

### 4.2 主导航

建议正式导航控制在五项：

```text
首页 / 项目 / 影集 / 随笔 / 关于
```

“此刻 Now”可以从首页的状态区域和关于页进入，不必挤占第一版主导航。

### 4.3 首页内容优先级

1. 姓名与一句真实介绍。
2. 当前关注方向和最近状态。
3. 四个主要入口。
4. 精选项目和最新随笔的文字列表。
5. 联系方式与更新时间。

首页不显示项目缩略图或照片预览。点击“影集”后，在页面离场转场中首次出现真实照片。

## 5. 页面规格

### 5.1 首页

#### 目的

建立身份、气质和站点入口，而不是展示所有成果。

#### 版式

- 12 列桌面网格，移动端 4 列网格。
- 首屏占满视口但不锁定滚动。
- 左上角为姓名或字标；右上角为当前地点时间和菜单。
- 中央是两至三行个人陈述。
- 下方以编号目录呈现项目、影集、随笔和关于。
- 页面底部提供精选内容的文字索引。

#### 交互

- 开场动画总时长控制在 0.8 至 1.2 秒，可跳过、不阻塞点击。
- 标题可使用极轻的字宽或字重响应，不使用跟随鼠标的光球。
- 栏目悬停时改变对齐、下划线位置和元数据，不显示照片。
- 页面滚动时，页码、日期或细线产生缓慢位移。
- 点击影集时背景由米白过渡到炭黑，并在离场阶段引入第一张照片。

#### 验收

- 首屏不出现照片、视频、照片缩略图或照片形态占位图。
- 关闭 JavaScript 后仍能看到完整介绍和导航。
- 任何开场动画都不能造成累计布局偏移。

### 5.2 项目列表与详情

#### 列表

- 采用文字目录而非圆角卡片网格。
- 每项包含年份、标题、角色、状态和一句结果摘要。
- 支持按研究、软件、实验或个人项目分类。
- 悬停只调整文字和布局；是否显示项目图片由后续内容决策确定。

#### 详情

- 依次说明背景、问题、个人角色、方法、结果和反思。
- 图片、图表或演示媒体按内容需要使用，不为了填满版面而添加。
- 对未公开或敏感项目提供概述，不暴露受限数据。

### 5.3 影集目录

#### 目的

让访客先选择一个故事，再进入大量图片。

#### 版式

- 背景切换为炭黑或深棕黑。
- 影集封面高低错落，保留原始横竖比例。
- 每组只使用一张强封面，不制作统一方形卡片。
- 元数据包括标题、地点、时间、照片数量和一句说明。

#### 交互

- 图片进入视口后渐进加载。
- 悬停出现地点、日期和拍摄信息。
- 封面以共享元素转场进入详情，不做突然弹窗。
- 可在“故事”“年份”“地点”三种视图间切换。

### 5.4 影集详情

提供两种互补模式：

#### Editorial View

- 默认模式，像摄影书一样纵向阅读。
- 图片尺寸、左右位置和留白形成节奏。
- 每组照片允许加入一小段文字，不要求每张照片都有说明。
- 保留跳到上一组、下一组和返回目录的明显入口。

#### 审片模式（替代自由光桌）

- 使用单张大图、进度和横向胶片索引展示整组影像。
- 支持前后箭头、键盘方向键、触屏横向滑动和点击进入灯箱。
- 保留年份、地点、主题和 EXIF 信息；筛选继续由故事模式与审片模式共享。
- 不使用自由拖动画布和不可控缩放，避免照片堆叠造成迷失或移动端操作负担。
- 提供语义化按钮和清晰焦点，满足键盘与辅助技术访问。

### 5.5 随笔

- 采用阅读优先版式，正文宽度约 38 至 46 个中文字符。
- 支持文章目录、脚注、边注、阅读进度和代码块。
- 动画应明显低于影集页面，避免干扰阅读。
- 文章元数据包括发布日期、更新时间、主题和预计阅读时间。

### 5.6 关于与此刻

关于页可使用一张本人照片，但不是强制项。页面包含：

- 简短介绍。
- 研究与工作关注方向。
- 兴趣、摄影和写作侧面。
- 经历时间线。
- 邮箱和外部链接。
- 简历下载（后续决定）。

Now 页面记录当前研究、阅读、所在地和生活重点，并显示最近更新时间。超过三个月未更新时应提示为历史快照，避免制造“当前”错觉。

### 5.7 404 页面

- 延续编辑式排版，不做独立的可爱插画模板。
- 可使用“丢失的底片”概念，但不自动加载大型素材。
- 提供首页、影集和最近内容入口。

## 6. 视觉设计系统

### 6.1 视觉基调

关键词：编辑、克制、触感、真实、私人、精确、可探索。

网站不追求完全光滑的 SaaS 视觉。适量纸张纹理、扫描颗粒、非对称图像比例、编辑批注和真实元数据用来建立人的痕迹。

### 6.2 暂定色彩

下列颜色是原型基线，需在真实内容加入后进行对比度和照片适配测试：

| 语义 | 暂定值 | 用途 |
|---|---:|---|
| Paper | `#F1EFE8` | 首页和阅读背景 |
| Ink | `#171714` | 主文字和深色背景 |
| Ash | `#A7A399` | 次要文字与分隔 |
| Darkroom | `#111110` | 影集沉浸背景 |
| Signal | `#B94A32` | 少量强调与状态 |

强调色只用于状态、选中和关键提示，不铺满大面积背景。

### 6.3 字体策略

- 中文标题：高质量宋体或现代衬线字体。
- 英文标题：具有编辑感的衬线字体。
- 正文：清晰的人文无衬线或易读宋体。
- 元数据：等宽字体或紧凑无衬线。
- 字体文件尽量自托管，避免第三方字体服务导致隐私、速度或大陆访问问题。
- 字体必须确认网页嵌入许可并记录来源。

具体字体在视觉原型阶段确定，不在方案阶段过早锁死。

### 6.4 网格与间距

- 桌面：12 列，外边距随视口变化，最大内容宽度约 1600px。
- 平板：8 列。
- 手机：4 列，关键内容保持单列阅读。
- 使用有限的间距刻度，避免每块内容随意设置间距。
- 非对称布局仍必须落在清晰网格上。

### 6.5 禁用的模板化语言

- 紫蓝渐变与发光球。
- 全站玻璃拟态。
- 大量圆角卡片和胶囊按钮。
- Bento Grid 首页。
- 无意义粒子、鼠标拖尾和漂浮图标。
- 通用机器人或宇宙插画。
- 空泛文案，如“探索无限可能”。
- 每个元素都缩放、弹跳或旋转。
- 伪终端、伪代码雨和与个人身份无关的科技装饰。

## 7. 交互与动效系统

### 7.1 原则

1. 每种动作都表达一种关系：进入、离开、展开、重排或聚焦。
2. 相同关系使用相同动作语言。
3. 交互反馈应在 100ms 内开始，长转场通常不超过 800ms。
4. 不使用动画掩盖内容等待；加载慢时显示真实占位状态。
5. 页面滚动默认保持原生行为。

### 7.2 动效分层

| 层级 | 场景 | 技术 |
|---|---|---|
| 微交互 | 链接、按钮、导航状态 | CSS transition |
| 页面关系 | 路由切换、共享标题 | View Transitions / GSAP |
| 内容重排 | 筛选、网格到全屏 | GSAP Flip |
| 滚动叙事 | 图片节奏、段落显现 | GSAP ScrollTrigger |
| 单张审片 | 胶片索引、方向键、横向滑动 | React + Pointer Events + CSS transition |
| 实验效果 | 少量图片畸变 | 经验证后可选 WebGL |

### 7.3 输入支持

- 鼠标：悬停、滚轮、拖动、点击。
- 键盘：Tab、Enter、Space、方向键、Esc。
- 触屏：点击和横向滑动切换，页面仍保留原生纵向滚动，不能依赖悬停。
- 辅助技术：语义按钮、标题层级、图片替代文本和明确焦点。

### 7.4 减少动态效果

检测 `prefers-reduced-motion: reduce` 后：

- 关闭视差、大面积缩放和连续跟随。
- 共享元素过渡替换为短淡入淡出。
- 审片模式保留直接切换，不播放强曝光或大面积缩放。
- 不自动播放装饰动画。
- 所有功能和信息保持可用。

## 8. 真实高清素材工作流

### 8.1 原型素材来源

第一阶段可以从以下来源选择风格统一的真实图片：

- Unsplash 免费开放图库：https://unsplash.com/license
- Pexels：https://www.pexels.com/license/

任何素材都必须下载到受控存储，不直接引用搜索结果页面或随时可能失效的外链。

### 8.2 正式素材优先级

1. 本人拍摄并确认可公开的照片。
2. 明确授权的亲友、合作摄影师或项目图片。
3. 许可清晰的公共素材，仅用于必要的过渡和原型。
4. 生成式图片默认不使用。

### 8.3 登记要求

每个外部素材在 `assets/licenses/asset-register.csv` 中记录：

- 内部素材 ID。
- 原始文件名和网页文件名。
- 作者与来源链接。
- 许可名称和许可链接。
- 下载日期。
- 是否需要署名。
- 允许用途与限制。
- 使用页面。
- 审核状态。

### 8.4 文件命名

建议规则：

```text
YYYY-MM-DD_location_subject_sequence.ext
2026-04-18_shanghai_rain-night_001.dng
2026-04-18_shanghai_rain-night_001_1600.avif
```

文件名使用小写 ASCII、连字符和稳定 ID，展示标题保存在内容元数据中，不依赖文件名表达完整语义。

### 8.5 图片处理

- 保留原始文件，不覆盖。
- 标准输出宽度暂定 480、768、1280、1600、2400px。
- 优先 AVIF，其次 WebP，并保留 JPEG 兼容版本。
- 为首屏关键图生成模糊占位或主色占位。
- 不把高像素原图直接发送给手机。
- 保留正确色彩空间，避免暗部和肤色因转换失真。
- 发布前检查并移除不需要的 EXIF、GPS 和设备信息。

## 9. 内容模型

### 9.1 影集

每个影集至少包含：

```yaml
title: 雨夜之后
slug: after-the-rain
date_start: 2026-04-18
date_end: 2026-04-20
location: Shanghai
summary: 一段不超过两句话的真实说明。
cover: photo-id
themes: [city, night, rain]
visibility: public
featured: true
```

单张照片元数据可包含：

```yaml
id: photo-id
file: 2026-04-18_shanghai_rain-night_001
alt: 雨后街口映出红色信号灯的倒影
caption: 可选说明
captured_at: 2026-04-18T21:17:00+08:00
location_public: Shanghai
camera_public: false
order: 10
```

精确地点默认不公开，尤其是住宅、私人场所或可能识别个人行程的位置。

### 9.2 随笔

```yaml
title: 标题
slug: example-note
published_at: 2026-08-13
updated_at: 2026-08-13
summary: 摘要
topics: [reading, research]
status: published
```

### 9.3 项目

```yaml
title: 项目名称
slug: example-project
year: 2026
role: 个人角色
status: ongoing
category: research
summary: 项目解决什么问题
featured: true
visibility: public
```

## 10. 技术架构

### 10.1 推荐技术栈

| 范围 | 选型 | 原因 |
|---|---|---|
| 网站框架 | vinext（Next.js App Router）+ TypeScript | Sites starter 原生支持、兼容 React 页面与 Cloudflare Worker 构建 |
| 复杂交互 | React Client Components | 只给审片、筛选等区域加载浏览器运行时代码 |
| 动画 | GSAP + Flip + ScrollTrigger | 统一完成重排、滚动和共享过渡 |
| 样式 | 原生 CSS / CSS Modules | 保持定制性，避免组件模板感 |
| 内容 | Markdown/MDX + 类型化 frontmatter | 内容与代码分离、迁移成本低 |
| 本地图片 | Next Image 或原生响应式 `<img>` | 生成正确尺寸、避免布局偏移 |
| 大量图片 | Cloudflare R2 + Images | 对象存储、转换与 CDN 分离 |
| 测试 | Playwright + axe + Lighthouse | 关键流程、无障碍与性能验证 |
| 代码质量 | ESLint + Prettier | 保持长期一致性 |

### 10.2 渲染策略

- 首页、项目、随笔、关于和影集正文尽量静态生成。
- 审片模式、筛选和照片查看器作为 React Client Component 加载。
- 默认不引入数据库和服务器端会话。
- 设备本地偏好可以使用 localStorage，例如上次浏览模式和是否显示元数据。
- 未来确需登录、私密影集或后台编辑时，再单独评估服务端能力。

### 10.3 为什么当前实现使用 vinext/Next 页面结构

- Sites 提供的官方 starter 已经是 vinext/Next App Router 结构，包含 Cloudflare Worker-compatible 构建、预览和托管配置。
- 当前网站仍按静态优先原则设计：静态页面负责内容，客户端组件只负责审片、筛选和查看器。
- 页面结构与 React 生态兼容，后续可以继续加入内容集合、动画和服务端能力。
- 该选择是实施层面的适配，不改变网站的内容优先、局部交互和可迁移原则。

如果将来增加账号、复杂后台、实时数据或大量 API，届时通过 ADR 重新评估是否继续使用 vinext/Next 的服务端能力，或迁移到标准 Next.js/Astro 等方案。

### 10.4 WebGL 使用边界

第一版审片模式使用 DOM、CSS 和 Pointer Events；单张大图、胶片索引、键盘与滑动不需要 WebGL。只有在以下条件全部满足时才引入 WebGL：

- 能带来无法用 DOM 合理实现的明确体验价值。
- 中端手机性能测试通过。
- 无 WebGL 时存在完整回退模式。
- 不增加不可接受的加载体积和维护复杂度。

## 11. 项目目录规划

根目录已经按以下职责建立：

```text
docs/          方案、决策、运行手册
design/        设计参考、线框图、交互原型
assets/        原图、网页图、许可登记
content/       影集、随笔和项目内容
src/           Astro 与 React 源码
public/        favicon、公开下载文件等
scripts/       图片、内容和发布辅助脚本
deployment/    托管、域名、迁移、恢复
tests/         自动化、性能与无障碍测试
archive/       已废弃但需保留的历史资料
```

正式初始化 vinext 后，内容可逐步放在 `content/` 或 `app/content/`，由页面构建阶段读取；迁移前需保留清晰映射，避免重复内容源。

## 12. 部署方案

### 12.1 默认全球方案

```text
本地开发
   ↓ Git push
GitHub repository
   ↓ 自动构建与预览
Cloudflare Pages
   ├── 页面、CSS、JavaScript
   └── 自定义域名与 HTTPS

Cloudflare R2
   └── 原图或大尺寸图片
         ↓
Cloudflare Images
   └── 响应式转换、格式协商和 CDN
```

优点：

- 静态页面部署简单。
- 每次改动都有预览地址。
- 图片与应用部署解耦。
- 迁移时可以导出完整静态站和原始素材。
- 初期可以在免费或低成本额度内运行。

### 12.2 中国大陆优先方案

如果主要访问者在中国大陆，采用同一份 Astro 静态构建，部署到腾讯云 CloudBase 或 COS + CDN。使用中国大陆资源前必须完成 ICP 备案；站点上线后还应按适用要求处理公安联网备案。

建议在开发开始前确定：

- 主要受众所在地区。
- 域名持有人和备案主体。
- 是否愿意购买满足备案要求的大陆云资源。
- 是否需要全球与大陆双部署。

### 12.3 环境划分

| 环境 | 用途 | 数据与素材 |
|---|---|---|
| Local | 开发与调试 | 本地样例、非敏感素材 |
| Preview | 每次合并前审阅 | 优化后的测试素材 |
| Production | 正式网站 | 审核通过的正式内容 |

Preview 应避免被搜索引擎收录，不能放入未获授权或私人素材。

### 12.4 域名与 HTTPS

- 优先注册稳定、易记的 `.com` 域名。
- 域名注册人与网站长期负责人保持一致。
- 开启自动续费，并使用独立恢复邮箱和多因素认证。
- DNS 记录和托管商配置写入运行文档，但不记录账号密码。
- 强制 HTTPS；HTTP 自动跳转 HTTPS。

### 12.5 发布流程

1. 在功能分支开发。
2. 自动生成 Preview。
3. 检查桌面与手机视觉、键盘、触屏、图片和性能。
4. 合并到主分支。
5. 自动部署 Production。
6. 执行上线冒烟检查。
7. 发现严重问题时回滚至上一稳定部署。

## 13. 性能预算

### 13.1 第一版目标

- 首页首次加载不下载任何照片资源。
- 首页关键 CSS 和字体尽量控制在可快速呈现的范围。
- 影集目录只预加载当前视口和即将进入视口的封面。
- 单张响应式图片根据设备尺寸加载，不发送原始大图。
- 交互帧率目标为 60fps；中端设备不得持续明显掉帧。
- JavaScript 主线程长任务应被拆分，审片交互保持轻量并按需加载图片。

### 13.2 Core Web Vitals 目标

- LCP：良好网络和常见设备下不超过 2.5s。
- CLS：不超过 0.1。
- INP：不超过 200ms。

这些目标在原型、内容导入和正式上线三个阶段都要重新测量，不能只测试空页面。

## 14. 无障碍要求

- 目标达到 WCAG 2.2 AA 的关键要求。
- 所有功能可通过键盘完成。
- 焦点状态清晰且不被动画遮挡。
- 图片提供与用途相符的替代文本；纯装饰纹理使用空替代文本。
- 正文、次要文字、链接和控件满足对比度要求。
- 不以颜色作为唯一状态提示。
- 审片模式同时提供前后按钮、键盘方向键和可直接选择的胶片索引。
- 自动动画可以暂停或因减少动态偏好而关闭。
- 页面标题、主标题和地标结构正确。

## 15. SEO 与分享

- 每个页面具有唯一标题、描述和 canonical URL。
- 项目、随笔和影集使用清晰的稳定 slug。
- 生成 sitemap.xml、robots.txt 和 RSS（随笔上线后）。
- 为公开图片提供正确尺寸和替代文本。
- 生成站点专属 Open Graph 分享图，不使用框架默认图。
- 添加 Person、Article 或 CreativeWork 等适合的结构化数据。
- Preview 环境设置禁止索引。

## 16. 隐私、安全与版权

### 16.1 隐私

- 默认不使用侵入式广告或跨站跟踪。
- 分析工具如需引入，优先选择轻量、隐私友好并可关闭的方案。
- 联系方式优先提供专用邮箱，减少暴露私人联系方式。
- 公开照片前检查人物授权、未成年人、门牌、证件、屏幕内容和精确位置。

### 16.2 安全

- 密钥只保存在托管平台的环境变量中。
- Git 仓库开启多因素认证和必要的分支保护。
- 定期更新依赖，但在升级前生成预览并运行测试。
- 限制图片上传接口；第一版不提供公开上传。
- 安全响应头在部署阶段配置并验证。

### 16.3 版权

- 所有外部素材必须具有明确许可。
- 即使许可不强制署名，也建议在影集说明或 Credits 中保留来源。
- 不使用搜索引擎结果图、社交平台截图或不明来源壁纸充当正式素材。
- 字体、图标、纹理和声音同样需要许可登记。

## 17. 备份、恢复与迁移

### 17.1 备份对象

- Git 仓库：代码、内容、配置和文档。
- 原始照片：至少保存在两个独立位置，其中一个不与工作电脑同盘。
- R2 或其他对象存储：定期生成清单并验证对象数量。
- 域名与 DNS：记录当前配置和到期时间。
- 环境变量：保存在安全密码管理工具中，不仅存在托管平台。

### 17.2 恢复目标

- 代码和页面可从 Git 仓库重新构建。
- 图片存储失效时，可以从原始备份重新生成网页版本。
- 托管平台不可用时，静态产物可迁移到另一家静态托管服务。
- 重大问题发生后，优先恢复上一稳定版本，而不是在线直接修补生产文件。

### 17.3 演练

至少每年进行一次恢复演练：在独立临时环境中从仓库、素材备份和环境配置重建网站，记录缺失步骤并修正文档。

## 18. 持续运营

### 18.1 内容节奏

建议采用可持续而非高频的更新方式：

- Now：1 至 3 个月更新一次。
- 随笔：有值得保留的内容时发布，不设置强制周更。
- 影集：每组经过筛选和编排后发布，避免自动同步全部相册。
- 项目：阶段性成果或角色发生变化时更新。

### 18.2 技术维护节奏

| 周期 | 维护内容 |
|---|---|
| 每次发布 | 构建、链接、关键流程和图片检查 |
| 每月 | 依赖安全提示、错误日志、流量与费用检查 |
| 每季度 | 依赖升级、性能复测、失效链接、内容时效检查 |
| 每年 | 域名续费、恢复演练、设计与信息架构复盘 |

### 18.3 内容退役

- 内容不直接删除，先将状态改为 archived 或移动到 `archive/`。
- URL 已公开时应设置重定向或说明页。
- 旧影集可保留原发布日期，并标记更新时间。

## 19. 成本控制

初期成本主要由域名、图片存储和可能的大陆备案资源构成。控制原则：

- 静态页面优先，避免长期服务器费用。
- 图片按实际设备尺寸转换，降低传输量。
- 设置托管费用提醒和上限。
- 不因一个小功能引入长期付费 SaaS。
- 每次增加后台、数据库或第三方分析前，记录收益、成本和退出方案。

## 20. 分阶段路线图

### Phase 0：方案与准备（当前）

交付：

- 项目目录。
- 总体方案。
- 决策、素材许可和内容模板。
- 待确认事项列表。

完成标准：后续开发不需要重新讨论项目基础方向。

### Phase 1：视觉与交互原型

范围：

- 首页。
- 影集目录。
- 审片模式。
- 影集详情。

交付：

- 桌面和手机可操作原型。
- 一套经过筛选的真实高清样例素材。
- 页面转场、筛选、全屏和减少动态效果。

完成标准：可以用真实浏览器判断网站是否具有独特且自然的气质。

### Phase 2：工程基线

- 初始化 Astro、TypeScript、React 和样式结构。
- 建立内容模型和图片处理脚本。
- 建立测试、Preview 和 Production 流程。
- 配置元数据、SEO、错误页面和基础安全。

### Phase 3：正式内容

- 替换原型素材。
- 导入首批项目、影集、随笔和关于内容。
- 完成版权、隐私和公开范围检查。
- 在真实内容下重新检查版式与性能。

### Phase 4：上线

- 绑定域名和 HTTPS。
- 完成最终浏览器、移动端、性能和无障碍验证。
- 配置备份、费用提醒和恢复资料。
- 发布并执行上线后冒烟检查。

### Phase 5：增强

只有基线稳定后再考虑：

- 私密影集或密码访问。
- 地图式探索。
- 内容后台或 CMS。
- RSS 和邮件订阅。
- 双语内容。
- 大规模图片虚拟化或局部 WebGL 效果。

## 21. 每阶段验收清单

### 产品

- 页面目的明确，没有空栏目。
- 首页无照片。
- 真实文案替换占位文案。
- 影集数量和照片数量经过策展。

### 设计

- 不存在模板化 AI 视觉元素。
- 布局在网格上有明确秩序。
- 真实图片风格一致，裁剪合理。
- 桌面和手机均经过人工检查。

### 交互

- 所有可点击元素有反馈。
- 键盘、触屏和鼠标均可操作。
- 浏览器返回与锚点正常。
- 减少动态效果模式可用。
- 动画不会阻塞内容与导航。

### 工程

- 构建成功。
- 没有密钥和未授权素材进入仓库。
- 图片具有尺寸、格式、替代文本和加载策略。
- 关键路径自动测试通过。
- Preview 与 Production 配置分离。

### 运营

- 可回滚。
- 可从备份恢复。
- 已记录域名、费用和续费责任。
- 文档与实际系统一致。

## 22. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 动效过多 | 阅读困难、手机掉帧 | 动效分层、性能预算、减少动态模式 |
| 高清照片过大 | 首屏慢、流量成本上升 | 响应式尺寸、现代格式、按需加载 |
| 素材许可不清 | 版权风险 | 强制登记、上线前审计 |
| 首页过于抽象 | 访客不知道网站用途 | 明确介绍、入口和最近内容 |
| 第二浏览方式过度实验 | 用户迷失 | 默认故事模式；审片模式保持单图、索引和明确前后关系 |
| 平台锁定 | 迁移困难 | 静态输出、内容文件化、原图独立备份 |
| 长期不更新 | Now 和内容失真 | 显示更新时间、允许历史快照 |
| 大陆访问不稳定 | 主要用户体验差 | 提前确认受众，必要时备案和大陆部署 |

## 23. 开工前待确认事项

下列选择会在原型或部署前确认，不影响当前方案成立：

1. 网站展示姓名、昵称或英文名。
2. 主要访问人群是否位于中国大陆。
3. 是否需要中英双语。
4. 第一批可公开照片的大致数量、题材和横竖比例。
5. 是否公开精确地点、设备和拍摄日期。
6. 项目内容偏研究档案还是求职作品集。
7. 是否需要密码保护的私人影集。
8. 域名候选和域名持有人。
